Introduction

Yalla Match helps players discover, join, and create local sports matches. If you use the app, these are the practices described for that use. If you do not agree, do not use the app.

Information the app collects

  • When you sign in with Google, the app sends a Google ID token, a Firebase notification token, and the platform (IOS or ANDROID) to the Yalla Match service.
  • Account data returned by the service can include name, email, Google identifier, photo, phone number if you add one, age, bio, sports, position, governorate, city, village, trust score, match statistics, and account status.
  • When you create a match: title, sport, stadium name, optional description, player counts, skill level, spots, price per player, governorate, city, village, address, contact phone, and match date and time.
  • Issue reports, suggestions, and reports about a match or another user that you submit in the app.
  • Local preferences such as language, dark mode, and guest mode, a device identifier created on the phone for guest session continuity, and cached copies of some matches and profile data.
  • Feedback or a report can include the app version and the device details shown in the support form.

How information is used

The visible uses are creating a session, showing the profile and matches, coordinating players, sending notifications the device allows, and handling support and reports. The app dependencies do not include an advertising SDK. The project draft says personal information is not used to show third-party ads and is not sold.

Needs confirmation: The “not sold” statement is written in the draft. It is not a contract visible inside the mobile app.

Needs confirmation: The app code does not show whether the service later uses data for any other purpose.

Location information

The reviewed Android and iOS permission lists do not request device location. Location in Yalla Match is the governorate, city, and village a person selects, plus the stadium name and address typed by the match organizer. Home can show a distance when the service includes one with the match.

Authentication and account information

The visible sign-in method is Google Sign-In with Firebase Authentication, followed by an exchange with the Yalla Match service. Access and refresh tokens are stored in the device secure storage. You can browse as a guest without an account, and some actions require signing in.

Notifications

The app requests notification permission and reads a Firebase Cloud Messaging token at sign-in. The notification types visible in the app include match activity, reminders, and attendance confirmation. Settings does not include a separate notification switch. Permission is controlled by the device.

Photos and profile information

You can take a profile photo with the camera or choose one from the photo library and upload it to the Yalla Match service. The iOS permission text says camera and photo library access are for the profile photo.

Third-party services

  • Google Sign-In and Firebase Authentication for sign-in.
  • Firebase Cloud Messaging and on-device local notifications.
  • The Yalla Match service at the address used by the app: https://yalla-match.menuflowx.com/

Needs confirmation: Hosting contracts, backups, and any processors that are not visible in the mobile app.

Data sharing

Account and match data are sent to the Yalla Match service. Sign-in and notification data pass through Google and Firebase. Match details, including the organizer phone number and address, are shown to people who open that match in the app. Another player's profile can be opened in the app. This page does not claim that data is never shared.

Data storage and security

Session tokens are stored in device secure storage, and the service address in the current version uses HTTPS. The Android configuration allows cleartext traffic, and the iOS configuration allows arbitrary loads. This page does not claim that every connection is encrypted or that all stored data is encrypted.

Needs confirmation: Server access controls, encryption at rest, and the backup policy.

Data retention

The project draft says data is kept while the account is active and as needed to run the app. It says an in-app deletion deletes or anonymizes account data on active systems, except data that must be kept for legal, security, dispute, or fraud-prevention reasons, and that leftover copies may remain in backups for a limited period. Data stored only on the phone can be removed by signing out, clearing app data, or uninstalling.

Needs confirmation: The app code does not set a number of days, and it does not prove what the server deletes. “A limited period” is not a confirmed duration.

User rights

You can edit part of your profile in Edit Profile, and a signed-in user can request deletion from Settings. The app does not include a tool to download a full copy of personal data.

Account and data deletion

The steps are explained on the Delete Account page. The in-app confirmation says the action cannot be undone and that the profile, matches, and data will be permanently deleted. What the server actually deletes still needs owner confirmation.

Children's privacy

The project draft says Yalla Match is not directed to children under 13, or under a higher digital-consent age where that applies, and that the app does not knowingly collect personal information from children under that age. A parent can email support and ask for that information to be deleted.

Needs confirmation: The app does not block account creation with an age gate. Profile age is optional, and the 12 to 55 range sent with a match is not a check of the account holder's age.

Changes to this policy

The project draft dated 12 August 2026 says the policy may be updated and the last-updated date revised. Inside the app, policy sections come from the policies service and may differ from this page until the owner publishes one text.
